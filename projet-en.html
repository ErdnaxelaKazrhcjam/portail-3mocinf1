The project

A personal website, designed, coded and published in class during weeks 4 to 6. It counts for 70% of the module's grade.

The topic

Your website introduces something you know well (a hobby, a club, a place, a game, a recipe, an artist…) to a specific audience, which you name from the start.

For example: “introducing the game of Go to chess players who have never played it”.

The schedule

No lessons on Thursday 19 November and Thursday 3 December: the project therefore runs over four Thursdays until mid-December.

  1. Homework for 26 November

    Choose a topic and an audience, write three sentences about the website's goal, list three or four pages and gather the content: texts, free images with their source, a YouTube video.

  2. Week 4, Thursday 26 November: design

    A lesson on user experience, a paper mockup of each page, a test in pairs, then creating the repository and the first push: the website is online from day one.

  3. Week 5, Thursday 10 December: build

    Several pages, a shared menu, a video, light images. Cross-testing: you visit a classmate's website and open GitHub issues for them.

  4. Week 6, Thursday 17 December: present

    Final touches, a code freeze at a set time, presentations, then the project fair.

The requirements

Structure

  • At least three pages linked by a shared menu, with index.html as the home page.
  • header, nav, main and footer on every page.
  • Headings in the right order, text written by you, lists and links.
  • An English version of each page, translated with AI, in a separate file (index-en.html…).

Content

  • At least four images, each with a useful alt.
  • A video embedded from YouTube.
  • The sources of images, fonts, figures and facts.
  • No personal data, and no photo of a person without their consent.

Style

  • A single style.css file, with rules on tags and on classes.
  • Text with good contrast against its background.
  • A website that is readable on a phone (responsive).

JavaScript and accessibility

  • At least two interactions that you can explain.
  • A website that can be browsed with the keyboard, using the Tab key.

User experience

  • No dark patterns… except a single, deliberate one that you can name during the oral.

Publication

  • The website is online on GitHub Pages and listed on this portal.

Assessment

How the project grade is split (70% of the module)
PartWeightWhat is assessed
Mockup15%Pages and navigation drawn, user experience choices, how closely the final website follows it, or justified changes
Final website35%Requirements, quality of the HTML and CSS, working JavaScript, content
Commits15%Regular work from one lesson to the next, one step per commit, clear messages, AI declared
Oral35%Presentation of the website and understanding of the code

The rules

  • The project is done in class: commits made outside lessons will be questioned.
  • AI is allowed if you declare it in the commit message and can explain every line.
  • No framework, CMS or website builder: HTML, CSS and JavaScript written by you.
